# Развёртывание Call QA на чистом сервере (Docker Compose)

Состав: `db` (PostgreSQL 16) + `app` (веб, API, очередь, ASR, оценка) + `nginx` (HTTPS). Конфиг только через `.env`.

## Требования к серверу
- Linux x86_64 (Ubuntu 22.04/24.04, Debian 12, RHEL/Rocky 9), Docker 24+ с плагином compose (или Podman 4+).
- 4+ ядра, 16 ГБ ОЗУ (GigaAM на CPU ≈ 3 с на минуту записи), диск от 50 ГБ (+ ~1 ГБ на 250 часов аудио MP3 — считать по клиенту).
- Исходящий интернет на установке (образы, pip, веса GigaAM ~1 ГБ при первом запуске) либо офлайн-пакет (см. «Не сделано»).
- Порты 80/443 наружу; БД и приложение наружу не публикуются.
- **LLM для оценки звонков — два способа, выбор в админке «Модели»:**
  1. **Локально** (`install.sh --with-llm`, с видеокартой NVIDIA `--gpu`): в compose поднимается Ollama, модели выбираются и скачиваются прямо в админке из каталога из 5 моделей (`app/llm_catalog.yaml`) или по имени; есть инструкция для ручной загрузки и своих GGUF. Тексты не покидают сервер. Для моделей 14B+ нужна карта от 12 ГБ, для 30B+ — 24 ГБ; на процессоре работает, но очень медленно.
  2. **Внешний API** (OpenAI-совместимый, облачный или свой сервер): адрес, ключ и модель вводятся в админке. Тексты расшифровок уходят на этот адрес — согласовать с клиентом (doc 07).
  Свой vLLM/LiteLLM вместо встроенного Ollama — задать `LLM_URL` в `.env`.

## Установка
```bash
git clone https://github.com/azalor-zh/call-qa.git callqa && cd callqa/deploy
sudo ./install.sh --domain callqa.client.kz --with-llm        # без видеокарты, локальные модели на процессоре
sudo ./install.sh --domain callqa.client.kz --with-llm --gpu  # с видеокартой NVIDIA
sudo ./install.sh --domain callqa.client.kz                   # без локальных LLM: оценка через внешний API
sudo ./install.sh --domain callqa.client.kz --weights /путь/к/gigaam   # свои веса GigaAM (если CDN недоступен)
```
RHEL/Rocky: Docker CE ставится из `https://download.docker.com/linux/rhel/docker-ce.repo`; метки SELinux (`:z`) и порты firewalld установщик настраивает сам.
Один запуск создаёт `.env` с паролями, сертификат, собирает и стартует систему, ждёт `/health`.
Вход: `https://<домен>/`, пользователь и пароль из `.env` (`ADMIN_USER`, `ADMIN_PASSWORD`). Сразу сменить пароль.

## Офлайн-установка (сервер без интернета)
1. На машине с интернетом и Docker: `./make-bundle.sh --models qwen3:14b --version 0.1.0` → `dist/callqa-bundle-0.1.0.tar` (образы, веса GigaAM, выбранные модели, исходники, контрольные суммы).
2. Перенести архив на сервер клиента (флешка), `tar xf callqa-bundle-0.1.0.tar && cd callqa-bundle-0.1.0`.
3. `sudo ./install-offline.sh --domain callqa.client.kz --with-llm` (на сервере должен быть установлен Docker). Скрипт проверит суммы, загрузит образы и модели и запустит установку без обращения в сеть.
4. Проверка: `cd repo/deploy && ./smoke-test.sh`.

## Проверка установки
`./smoke-test.sh` — контейнеры, `/health`, редирект на HTTPS, вход, страницы «Модели» и «Сервер», каталог, Ollama, таблицы БД. Код выхода 0 — всё хорошо.

## Первый запуск (в админке)
1. «Модели»: выбрать «Модель на нашем сервере» → скачать модель из каталога → выбрать её → «Сохранить» (или «Внешний API» → «Проверить подключение»). Выбрать движок распознавания (`gigaam-rnnt` по умолчанию; Whisper на процессоре тоже есть в образе, но очень медленный).
2. Создать учётку клиента, загрузить/настроить чек-листы (шаблоны: `../templates/`), справочник сотрудников.
3. Срок хранения аудио, лимит длины записи (там же).
4. Прогнать 2–3 тестовых звонка, сравнить с оценкой человека (doc 05).
5. Сертификат: заменить файлы `volumes/certs/callqa.{crt,key}` на боевые (Let's Encrypt/корпоративный), `docker compose restart nginx`.

## Эксплуатация
| Действие | Команда |
|---|---|
| Состояние | `docker compose ps`, `curl -k https://localhost/health` |
| Логи | `docker compose logs -f app` |
| Бэкап БД (cron 03:17) | `./backup.sh` → `volumes/backups`; аудио — `volumes/data/audio` копировать отдельно |
| Обновление | `git pull && docker compose up -d --build` (перед этим `./backup.sh`; очередь лучше дождаться пустой) |
| Откат | вернуть прежний тег `CALLQA_VERSION`, при смене схемы — восстановить дамп |
| Восстановление БД | `gunzip -c файл.sql.gz \| docker compose exec -T db psql -U callqa -d callqa` |

## Автосбор записей с АТС
`../collector/` ставится на хост клиента (systemd timer) или в отдельный контейнер; конфиг `collector.toml` с ключами — вне репозитория. См. `../collector/README.md`.

## Не проверено / не сделано
- Проверено 2026-11-05 на RHEL 10.2 (8 ядер, 15 ГБ, Docker CE 29.9, SELinux Enforcing, без GPU): онлайн-установка, сборка образа из `requirements.lock`, `smoke-test.sh`, загрузка qwen3:8b из админки, тестовый звонок 19 с (распознавание 3 с, оценка на процессоре 247 с). Не проверено: Ubuntu, Podman, GPU, офлайн-пакет, качество оценки моделей каталога.
- Веса GigaAM `install.sh` берёт из релиза нашего репозитория (тег `weights-gigaam-v3`, архив `gigaam-v3.tar` ~850 МБ, обязательная проверка sha256), а не с CDN Сбера: 2026-11-05 у него истёк сертификат и загрузка падала. Репозиторий публичный, токен не нужен. Для своего форка с приватным релизом задайте `GH_TOKEN` и `GIGAAM_REPO=<владелец>/<репозиторий>` (при sudo: `sudo --preserve-env=GH_TOKEN,GIGAAM_REPO ./install.sh …`). После переноса репозитория в организацию поменяйте значение `GIGAAM_REPO` по умолчанию в `install.sh`. Если загрузка не удалась, остаются запасные пути: `--weights <папка>` или офлайн-пакет; при первом звонке приложение ещё попробует CDN Сбера.
- Оценка 8B на процессоре — ~4 мин на короткий звонок: для боевой нагрузки нужна видеокарта (`--gpu`) или внешний API.
- GPU-вариант образа (CUDA, Whisper на видеокарте) и офлайн-установка (архив образов и весов) не сделаны.
- Автообновление схемы БД между версиями — только `CREATE TABLE IF NOT EXISTS`; для новых колонок нужны миграции.
- Лицензионный ключ и срок (как в fabric-inspection) не реализованы.
